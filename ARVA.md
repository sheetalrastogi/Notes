# Security Automation

Reduced manual security testing effort by 40% while increasing security coverage across all sprint releases.

**Value Added**
- Improved security assessments / Penetration tests coverage by
  - Automating Penetration / Offensive test as part of secure development
  - Test pipeline resilience against malicious inputs.
  - Validate continous monitoring for **audit logs** for malicious use. 
  - Actively contributed towards **security requirements**, **compliance controls**, **threat scenarios**, **abuse cases**, and **risk-based testing** recommendations during SDLC.
  - Investigate **security incidents**, **identify root causes** of data breaches, validate fixes, perform regression security testing, and strengthen defense mechanisms. 


**Security Testing & Offensive Security Contributions**

  - Enhanced **application security** & **vulnerability assessment** by automating security coverage providing better validation beyond QA testing (Integrating tools based security assessment Nmap, Wireshark, Burp Suite, OWASP ZAP Proxy via  automation scripts). 
  - Promoted a **Security-by-Design** approach by working closely with development teams to **establish secure coding practices** by **embedding automated security checks such as SAST, DAST, dependency vulnerability scanning, and secret detection** during development phase.
  - Automated testing for **IAM permissions**, **network security configurations**, **container security posture**, and **infrastructure misconfigurations** 
  - Establish **Secure coding standards**, implement **Security-by-Design principles** by integrating SAST, DAST, dependency scanning, and secrets scanning via Automation scripts.
  - Validate **Data segregation controls**, **access restrictions** between zones, **encryption enforcement**, **PII exposure** prevention across layers.
